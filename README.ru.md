## Что такое Centra AI?

Centra AI — частная платформа постоянных ИИ-агентов, разработанная Sidiora Labs. Она предназначена для задач, которые невозможно надёжно завершить одним запросом: разработки программного обеспечения, сложных исследований, работы с браузером и файлами, координации нескольких специалистов, создания артефактов и продолжения работы между сессиями без потери контекста.

В центре системы находятся два агента:

- **Neo** — основной агент. Он исследует, рассуждает, использует инструменты, создаёт артефакты, управляет текущей работой и сопровождает задачу дольше одного ответа модели.
- **Ion** — технический агент и среда разработки. Он работает с реальными проектами, терминалами, файлами, тестами, предпросмотрами и инструментальными цепочками в изолированном рабочем пространстве.

Их дополняют **Workforce** — управляемый слой параллельного выполнения сложных задач — и **Neo Computer**, единое пространство для источников, предпросмотров, артефактов, изменений и подтверждений из рабочей среды.

Centra не строится вокруг истории сообщений. Диалог служит интерфейсом управления, а сам продукт — это рабочая система, которая действует за ним.

## Ключевые принципы

### Постоянное когнитивное состояние

Centra сохраняет идентичность, память, активные цели, подтверждения и незавершённую работу. Cortex и Neocortex позволяют восстановить, что уже произошло, что остаётся сделать и на каких данных основаны выводы системы — даже после перезапуска процесса или смены контекстного окна.

### Реальные среды выполнения

Агенты работают с файлами, терминалами, браузерами, кодовыми базами, базами данных, локальными сервисами, медиасредствами и внешними системами. Разработка ведётся в настоящем проектном окружении с менеджерами пакетов, тестами, предпросмотрами и готовыми к загрузке результатами.

### Проверяемые результаты

Источники, цитаты, действия инструментов, артефакты, контрольные точки и результаты проверки являются частью продукта. Centra отделяет убедительно звучащий ответ от действительно выполненной работы и сохраняет данные, необходимые для аудита.

### Долгосрочные задачи

Работу можно декомпозировать, ставить в очередь, возобновлять, корректировать и продолжать. Агенты координируют специализированные процессы, восстанавливаются после прерываний и не пытаются уместить крупную задачу в один запрос.

### Явные границы полномочий

Обычные обратимые действия выполняются быстро. Чувствительные записи, внешние побочные эффекты, финансовые операции и другие значимые действия проходят через явные границы полномочий и подтверждения. Путь принятия решения сохраняется вместе с результатом.

### Изоляция пользователей

В производственной архитектуре каждый пользователь получает отдельную агентную среду и собственную границу постоянного состояния. Центральные сервисы аутентифицируют, маршрутизируют, учитывают использование и пробуждают эти среды, не объединяя пользовательские рабочие пространства в общий пул выполнения.

## Архитектура

Centra — монорепозиторий независимо собираемых сервисов и клиентов. Агенты могут обладать широкими полномочиями внутри выделенной пользовательской среды, но исходный код демона, идентичность платформы, управление хостом и учётные данные остаются за её пределами.

| Компонент | Назначение |
| --- | --- |
| `neo/` | Основной агент, потоковый цикл общения, инструменты, память, автоматизация и доставка результатов. |
| `ion/` | Технический агент, интеллект проекта, рабочая среда разработки и политика безопасности. |
| `workforce/` | Управляемая декомпозиция, координация и надзор за многоагентной работой. |
| `client/` | Продуктовый клиент Next.js: чат, разработка, Neo Computer, рабочие поверхности и настройки. |
| `neocortex/` | Детерминированный движок памяти и доказательств с точным восстановлением состояния. |
| `cortex/` | Постоянная подсистема памяти на Go и совместимый путь хранения. |
| `executor/` | Жизненный цикл действий, диспетчеризация инструментов и контрольные точки. |
| `router/` | Аутентификация, маршрутизация пользователей, подготовка и пробуждение сред. |
| `gateway/` | Доступ к моделям, учёт использования, политики и маршрутизация провайдеров. |
| `chronos/` | Расписания, события пробуждения, повторяющаяся работа и проактивная доставка. |
| `vault/` | Конвертное шифрование и границы защиты пользовательских данных. |
| `sandboxd/` | Изолированные рабочие пространства и инфраструктура предпросмотра. |

Подробнее об остальных модулях и идентификаторах, сохранённых для совместимости, см. в [ARCHITECTURE.md](ARCHITECTURE.md) и [BRANDING.md](BRANDING.md).

## Быстрый старт

### Требования

- Go 1.26.5
- Node.js 22+
- pnpm 10.33+
- Python 3.11+
- GNU Make 4.x
- Docker с Buildx для сборки контейнеров

### Клонирование и сборка серверной части

```bash
git clone https://github.com/Sidiora-Labs/centra-llm-agents.git
cd centra-llm-agents

make build
make install
```

`make build` собирает пятнадцать Go-модулей, перечисленных в корневом Makefile. `make install` помещает исполняемые файлы в `./bin`.

### Запуск клиента

```bash
cd client
corepack enable
pnpm install
pnpm dev
```

По умолчанию клиент запускается на `http://localhost:3000`. Для сервисов среды выполнения необходимы переменные окружения, описанные в документации соответствующего модуля и конфигурации развёртывания.

### Локальная проверка

```bash
make ci

cd client
pnpm build
```
